# Data dictionary

## Prediction files (`<deployment>.json`, `<deployment>_repeat_<A|B>.json`, `<deployment>_<A|B>.json`)
| Field | Meaning |
|---|---|
| `dataset`, `arm`/`format`, `repeat` | dataset name, deployment (bf16, nf4, fp4, fp8, int8), repeat label |
| `selection_sha256` | SHA-256 of the canonical JSON of the frozen input selection the run used |
| `model_revision` | pinned Hugging Face revision (Llama Guard 3 runs) |
| `finished` | `true` only when every selected input has a record |
| `records[].id` | input identifier, unique within the selection |
| `records[].gold` | benchmark label mapped to `safe`/`unsafe` |
| `records[].output` | raw text generated by the guard (greedy decoding) |
| `records[].binary` | verdict parsed from `output`: Qwen3Guard `Safety: Unsafe/Controversial` -> `unsafe`, `Safe` -> `safe`; Llama Guard 3 first non-empty line |
| `records[].category`, `subgroup`/`task` | benchmark category metadata (e.g. XSTest prompt type) |

## Selections and manifests
- `selection.json` / `llama_selection.json`: the frozen inputs (`messages` in chat format, `gold`, `category`, token count, `prompt_hash`).
- `manifest.json` / `llama_manifest.json`: source repository and split, exclusion counts, label counts, seeds, token limits, `selection_sha256`.
- `subset_manifest.json` (repeatability folders): the 256-input (128 per class) subsets and the hash of the full selection they were drawn from.

## Summaries and logs
`*_summary.json`, `summary_table.csv` and `*.log` files were written by the runners at run time. All numbers in the paper are recomputed from the per-record files, not taken from these summaries. `wildguard_prompt.log` records that WildGuardTest could not be run because the dataset is access-gated.
